# Changelog

All notable changes to the ferrovgl crates are documented in this file. The
published crates (`ferrovgl`, `ferrovgl-core`, `ferrovgl-draw-sw`,
`ferrovgl-fonts`, `ferrovgl-widgets`, `ferrovgl-sdl`, `ferrovgl-wasm`,
`ferrovgl-embedded`, `ferrovgl-examples`) share one version and this one
changelog.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the crates follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(before 1.0, a minor version bump may break the API). Entries after 0.1.0 are
generated by release-plz from Conventional Commits; see
[CONTRIBUTING.md](CONTRIBUTING.md#releases).

ferrovgl is an independent project, not affiliated with LVGL LLC. "LVGL" is a
trademark of LVGL LLC.

## [0.1.0] - 2026-10-25

First public release: a pure-Rust, `#![no_std]` + `alloc` reimplementation of
LVGL v9.6.0 (commit `80ca777`), ported 1:1 from the C sources and verified
against upstream's reference images.

### Added

- **`ferrovgl-core`**: arena-based object tree with copyable handles and a
  safe `Ui` context; the complete style system (local/shared styles, selectors,
  inheritance, transitions, style cache); event dispatch with LVGL's event
  order, deferred deletion and external event data; flex and grid layouts;
  scrolling (scrollbars, snapping, scroll animations, scroll-on-focus);
  pointer, keypad, encoder and button input devices with focus groups; timers,
  ticks and animations; the display/refresh pipeline (partial, direct and full
  render modes, invalidation, layers); draw buffers in every format upstream's
  software renderer uses; object snapshots (`snapshot` feature); the observer
  subject/observer system (`observer`); object ids (`obj-id`); BiDi and
  Arabic/Persian shaping (`bidi`, `arabic-persian-chars`); optional `float`,
  `libm` and `log` support.
- **`ferrovgl-draw-sw`**: port of `src/draw/sw`: fills, borders, box shadows
  with the shadow cache, linear/radial/conic gradients (`complex-gradients`),
  rounded-rectangle and other masks, letters, images with rotation/scale/
  recolour/tiling, lines, arcs, triangles, blur, layer composition and
  blending for RGB565 (and swapped), RGB888, XRGB8888, ARGB8888,
  premultiplied ARGB8888, L8, AL88, A8 and I1, each behind a `cf-*` feature.
- **`ferrovgl-fonts`**: Montserrat 8-48 (even sizes) and compressed
  Montserrat 28, UNSCII 8/16 and DejaVu 16 Persian/Hebrew, converted from
  LVGL's glyph tables into `.lvfnt` blobs read in place; one feature per font.
- **`ferrovgl-widgets`**: the 13 widgets of the 0.1 scope (label, button,
  image, bar, slider, switch, checkbox, arc, line, LED, spinner, button
  matrix, text area) with their observer bindings, and the default and simple
  themes (light/dark, DPI scaling, per-display ownership).
- **`ferrovgl-sdl`**: SDL2 desktop simulator: fixed-size window, XRGB8888
  direct-mode presentation, mouse/keyboard/wheel input, `hello`,
  `interactive` and `lv_examples` examples.
- **`ferrovgl-wasm`**: browser backend: Canvas2D presentation of partial,
  direct and full render modes, pointer/keyboard/wheel input, a
  `requestAnimationFrame` loop, a wasm-bindgen `WebDisplay` API and a demo
  page with a widget gallery and the ported examples.
- **`ferrovgl-examples`**: 132 ports of upstream `lv_example_*` functions
  (get started, styles, animations, events, flex, grid, scrolling and all 13
  widgets), shared by the SDL and browser demos.
- **`ferrovgl-embedded`**: placeholder crate for the v0.2 embedded-graphics /
  embedded-hal adapters (no API yet).
- **`ferrovgl`**: umbrella crate re-exporting the above behind the `draw-sw`,
  `fonts`, `widgets` (default), `sdl`, `embedded` and `std` features.

### Verified

- **140 upstream reference images match byte-exactly** (RGB tolerance 0,
  800x480 XRGB8888, upstream `tests/ref_imgs`) across label, button, image,
  bar, slider, switch, checkbox, arc, line, LED, spinner, button matrix, text
  area, flex, grid, scroll, style, snapshot, blur, line/arc/triangle/shadow
  drawing and RTL scenes. Reference images are never edited or regenerated.
- The core, renderer, fonts and widgets build for `thumbv7em-none-eabihf` and
  `thumbv6m-none-eabi` (`no_std`); a label + button binary is about 200 KB of
  `.text`. `unsafe` code is confined to two modules and checked with Miri.
- Three coverage-guided fuzz targets (style operations, text breaking, tree
  mutation) live in the separate `fuzz/` workspace.
- 1519 of 2899 public upstream functions and aliases (52.4 %) have a Rust
  counterpart; `docs/src/mapping.md` lists them all.

### Known limitations

- Widgets outside the 0.1 scope are missing: chart, keyboard, table,
  dropdown, roller, list, menu, msgbox, tabview, calendar, canvas, scale,
  span, spinbox, tileview, window, image button, animation image and others,
  as are `lv_anim_timeline` and the examples that need them or large assets.
- No file system drivers, image decoders (PNG, JPEG, BMP, GIF, ...), decoder
  registry, image cache, FreeType/TinyTTF or binary font loading at run time;
  images come from in-memory draw buffers or font symbols.
- No translation subsystem, object property reflection, XML, gesture
  recognition, grid navigation, multi-touch or IME composition. The
  `gridnav`, `gesture-recognition` and `binfont` features of `ferrovgl-core`
  and the `ttf` feature of `ferrovgl-fonts` are reserved and have no effect
  yet.
- Single-threaded software rendering only (`LV_USE_OS == LV_OS_NONE`): no
  parallel draw units, GPU/HW accelerators, ThorVG vector graphics, 3D
  textures or custom draw-buffer allocator/cache handlers.
- Some packed ARGB formats accepted by snapshots are not yet rendered by the
  software renderer.
- The SDL backend has a fixed-size single buffer (no resizing, rotation,
  offsets or other pixel formats); the browser backend does not resize the
  display or support rotation/offsets.
- `ferrovgl-embedded` is empty until 0.2.
- The API is pre-1.0 and will change; MSRV is Rust 1.97.
